# Revisões do incremento

Preencher incremento, responsável, data e evidências. Marcar itens somente após revisão real. Falhas devem receber um ID no registro de defeitos.

## Revisão de projeto

- [ ] Requisitos e exclusões definidos.
- [ ] Responsabilidades e dependências das classes coerentes.
- [ ] Fórmulas, centavos, unidades, arredondamento e datas especificados.
- [ ] Zero, prejuízo, entradas inválidas e várias plataformas considerados.
- [ ] Vínculos, exclusões, transações e migrações definidos quando aplicáveis.
- [ ] Critérios de aceite cobrem os riscos do incremento.

## Revisão de código futura

- [ ] Alteração corresponde ao projeto revisado.
- [ ] Cálculos isolados e sem dupla contagem de despesas ou quilômetros.
- [ ] Valores monetários preservam precisão.
- [ ] Falhas de persistência e entradas inválidas recebem tratamento.
- [ ] Testes relevantes conferem resultados independentes da implementação.
- [ ] Código não contém dados reais, segredos ou arquivos gerados indevidos.
- [ ] Defeitos encontrados registrados e correções verificadas.
